## 背景冲突如何处理

以前有三处逻辑：页面内联背景、main.js 快速切换、set.js 原壁纸选择。
它们写同一个 body 背景，但快速切换不保存壁纸模式，异步初始化只改变量，刷新又恢复另一套设置。

现在背景由 `js/set.js` 统一管理：

- `background.webp` 是确定的本地默认图，CSS 在脚本不可用时也显示它。
- 图片按钮依次切换 `background.webp` 与 `background1/2/3.webp`，同时把模式切回本地并保存选择。
- 每日一图、随机风景、随机动漫保留，通过已有壁纸设置面板选择。
- 新图片加载成功后再显示；失败或等待超过 8 秒就显示本地默认图。
- 在线图片失败时保留所选在线模式，下次刷新可以重新尝试。
- 递增请求编号保证旧请求晚回来时不会盖掉新选择。
- 设置保存到 localStorage，并兼容旧 `bg_img` Cookie；无效值恢复默认设置。

## 模糊按钮为什么数值变了，画面却没变

加载动画结束时，父级 section 被设成 `filter: blur(0px)`。
虽然肉眼上没有模糊，它仍是一个非 none 的 filter，导致内部卡片的 backdrop-filter 无法采样 section 外的 body 壁纸。
这个机制也在 [CSS Filter Effects 的 Backdrop Root 草案](https://drafts.csswg.org/filter-effects-2/#BackdropRoot)中有说明。

已在真实 Chrome 对照未修改的 1.4.1 复现：卡片计算值变化到 16px，而低 / 高档截图像素完全相同。
修复后加载完成使用 `filter: none`，并将模糊变量统一放到 :root，由卡片继承。
设置脚本提前独立初始化，第三方提示库失败也不会中断按钮。

按钮按低 → 中 → 高循环，初始为中，直接显示档位，并支持键盘回车。
模糊作用于卡片等玻璃区域，壁纸本身保持清晰。
切换用内存状态计算，localStorage 不可写时也能连续切换；能否跨刷新保存取决于浏览器存储权限。
