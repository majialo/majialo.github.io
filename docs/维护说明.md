# 维护说明

## 保存当前项目

以下命令在 `D:\1.5.0` 运行。初次保存前先查看文件，确认要跟踪的内容：

```powershell
git status --short
git add README.md .gitignore .github docs scripts chinese
git diff --cached --stat
git commit -m "保存 1.5.0 项目与整理说明"
git tag v1.5.0
```

本次整理只准备文件，没有自动执行提交或打标签。旧文件夹保留，可继续作为历史对照。
首次提交日期是实际保存日期，不能代表之前两年的修改时间。

## 每改好一件事，保存一次

```powershell
git status --short
git diff
# 把下面路径替换成这次实际改动的文件
git add chinese/index.html
git diff --cached
git commit -m "修改首页导航"
```

查看历史：`git log --oneline --decorate`。
一个提交可以是修一个链接，也可以是换一套背景，不必等到凑够一个大版本才保存。
发布一个确认可用的新版本时，再用 `git tag v1.5.1` 标记；同一个标签不要重复使用。

## 旧版本怎么接进来

已找到的目录是 `D:\1.2.1`、`D:\1.2.2`、`D:\1.3.2`、`D:\1.4.1`。
可以另建一个归档仓库，依次导入每个目录的站点快照，每个快照一个提交和标签。
不要复制旧 `.git` 到当前仓库，也不要把全部版本文件夹堆进当前站点。
1.4.1 与整理前的 1.5.0 内容相同，历史记录应如实注明。
尚未找到的 0.80 等版本，等有原始文件时再补。

## 本地确认改动

1. 运行 `scripts/Start-Preview.ps1`，打开本地地址。
2. 测试搜索回车、特殊字符、空输入。
3. 测试背景、模糊设置与刷新后的状态；在线壁纸失败时应看到本地默认图。
4. 检查宽屏、窄屏菜单和更多面板。
5. 打开开发者工具，检查控制台报错与 Network 失败请求。
6. 音乐可播放时，在搜索框输入带空格的文字，确认不会误触音乐快捷键。

如果改了文件但页面仍旧，检查 Application 中的 Service Worker 与缓存，清理该站点缓存后再刷新。
不要只依据文件保存成功判断浏览器效果。

## 背景设置现在如何维护

`chinese/js/set.js` 的 `LOCAL_BACKGROUNDS` 是本地背景列表，`ONLINE_BACKGROUNDS` 是在线来源。
默认图同时由脚本的 `DEFAULT_BACKGROUND` 和 CSS 的 body 背景指定；更换默认图时同步修改这两处。
快速背景按钮与设置面板共用状态，新增逻辑应接到这个模块，避免在 main.js 或 HTML 中另写背景切换。
三档卡片模糊参数也在 `set.js` 的 `BLUR_LEVELS` 中。

加载结束后 section 的 filter 必须为 none，不要再以 blur(0px) 代替，否则会隔断卡片采样背景。
